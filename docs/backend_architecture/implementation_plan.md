# 費用最小化・負荷軽減 バックエンドアーキテクチャ提案

## 目的
「費用がかからない範囲で構成できるよう負荷をできるだけ抑える」という要件を満たすため、`spec.md`記載の「Cloud Functions + Firestore」によるバックエンド構成を、よりスケーラブルかつ完全無料の「静的JSON生成・配信アーキテクチャ」へ変更する計画です。

## 課題定義
- **Firestoreの問題**: 無料枠（1日5万回読み取り）では、アプリユーザーが増加すると容易に超過し課金が発生。
- **Cloud Functionsの問題**: 呼び出し回数や時間による従量課金が発生しうる。
- APIの頻繁な利用は負荷につながる。

## 提案する新アーキテクチャ（サーバーレス×静的配信）

バックエンドのアプリ処理（動的サーバー）を廃止し、**GitHub Actions + CDNホスティング（Firebase Hosting or GitHub Pages等）** による事前データ生成に置き換えます。

1. **データ取得・整形**: GitHub Actionsが定期実行（cron）機能で、気象庁APIと5374.jpのCSVをそれぞれ必要な頻度でフェッチし、アプリが利用しやすい形式（JSON）に変換します。
2. **静的キャッシュ配信**: 作成したJSONファイルはそのまま静的ホスティングへ自動デプロイします。アプリはDBではなくこの「静的URL（JSONファイル）」を直接ダウンロードします。
3. **コストと負荷の排除**: CDNのエッジサーバーが配信を担うため、何万人・何十万人がアクセスしてもこちらのサーバー・DBに対する負荷や課金は発生しません。
